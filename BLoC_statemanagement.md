# Enterprise Flutter BLoC Architecture & AI Editor Directives

This document defines the standardized engineering architecture and machine-readable instruction set for Flutter applications powered by the BLoC pattern. It establishes direct Repository-pattern architecture, model serialization standards using `json_serializable` and `Equatable`, concurrency patterns, and UI widget rules.

## 1. Architectural Principles

The application follows a clean, feature-driven structure without over-engineering:

* **No Use Cases / Interactors**: BLoCs interact directly with Repositories.

* **No Dedicated Data Sources**: Repositories directly handle API calls (e.g., via Dio/Http) or local database operations, exposing clean Dart methods or reactive streams to the BLoCs.

* **Unidirectional Data Flow (UDF)**:

  * **Events** are dispatched from the UI to the BLoC.

  * **States** are emitted from the BLoC to the UI.

  * **Repositories** return domain models or `Stream<T>` pipelines.

```
┌────────────────────────────────────────────────────────┐
│                   Presentation Layer                   │
│   ┌─────────────────────┐       ┌──────────────────┐   │
│   │  Flutter UI Widgets │ ◄───► │   BLoC / Cubit   │   │
│   └─────────────────────┘       └─────────┬────────┘   │
└───────────────────────────────────────────┼────────────┘
                                            │ calls directly
                                            ▼
┌────────────────────────────────────────────────────────┐
│                    Repository Layer                    │
│   ┌────────────────────────────────────────────────┐   │
│   │  Repository (Handles HTTP / DB / Local Cache)  │   │
│   └───────────────────────┬────────────────────────┘   │
└───────────────────────────┼────────────────────────────┘
                            │ parses into
                            ▼
┌────────────────────────────────────────────────────────┐

│   ┌────────────────────────────────────────────────┐   │
│   │   Models (Equatable + json_serializable)       │   │
│   └────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────┘

```

## 3. Model Specifications: `json_serializable` + `Equatable`

All models representing entities, responses, or local state must adhere to three non-negotiable rules:

1. **Extend `Equatable`**: Implement value equality via `props`.

2. **`@JsonSerializable()` Annotation**: Code-generate JSON serialization (`part '<name>.g.dart';`).

3. **Deep Immutability**: All fields must be `final`. Any modifications must occur through `copyWith()`. Never mutate collections in place.

### Standard Model Blueprint

```
import 'package:equatable/equatable.dart';
import 'package:json_annotation/json_annotation.dart';

part 'product_model.g.dart';

@JsonSerializable(explicitToJson: true)
class ProductModel extends Equatable {
  final String id;
  final String title;
  final double price;
  final bool isAvailable;
  final List<String> tags;

  const ProductModel({
    required this.id,
    required this.title,
    required this.price,
    this.isAvailable = true,
    this.tags = const [],
  });

  /// Factory constructor connecting generated _$ProductModelFromJson
  factory ProductModel.fromJson(Map<String, dynamic> json) =>
      _$ProductModelFromJson(json);

  /// Method connecting generated _$ProductModelToJson
  Map<String, dynamic> toJson() => _$ProductModelToJson(this);

  /// Immutability helper for modifications
  ProductModel copyWith({
    String? id,
    String? title,
    double? price,
    bool? isAvailable,
    List<String>? tags,
  }) {
    return ProductModel(
      id: id ?? this.id,
      title: title ?? this.title,
      price: price ?? this.price,
      isAvailable: isAvailable ?? this.isAvailable,
      tags: tags ?? this.tags,
    );
  }

  @override
  List<Object?> get props => [id, title, price, isAvailable, tags];
}

```

## 4. BLoC vs. Cubit Decision Heuristic

| **Scenario** | **Choice** | **Reason** | 
| **Search / Text Input** | **BLoC** | Requires debouncing and cancellation (`restartable`). | 
| **API Mutations / Form Submission** | **BLoC** | Requires duplicate prevention (`droppable`). | 
| **Multi-Step Workflows** | **BLoC** | Traceable Event-to-State transitions via `BlocObserver`. | 
| **Simple UI Toggles / Tabs** | **Cubit** | Synchronous, local changes do not require event ceremony. | 
| **Pure View State (Expansion, Themes)** | **Cubit** | Minimalist logic without stream manipulation. |

## 6. Concurrency & Stream Transformers

Unbounded event triggers cause race conditions and network waste. Register explicit transformers on BLoC event listeners using `package:bloc_concurrency` and `rxdart`:

```
import 'package:flutter_bloc/flutter_bloc.dart';
import 'package:bloc_concurrency/bloc_concurrency.dart';
import 'package:rxdart/rxdart.dart';

// Custom debounce transformer
EventTransformer<E> debounce<E>(Duration duration) {
  return (events, mapper) => events.debounceTime(duration).switchMap(mapper);
}

class ProductBloc extends Bloc<ProductEvent, ProductState> {
  final ProductRepository _repository;

  ProductBloc(this._repository) : super(const ProductInitial()) {
    // 1. RESTARTABLE + DEBOUNCE: Cancels previous call when new query arrives (Search)
    on<SearchQueryChanged>(
      _onSearchQueryChanged,
      transformer: debounce(const Duration(milliseconds: 300)),
    );

    // 2. DROPPABLE: Ignores new taps until the current action completes (Checkout/Submit)
    on<ProductPurchased>(_onPurchased, transformer: droppable());

    // 3. SEQUENTIAL: Executes strictly in FIFO queue (Transaction/Sync operations)
    on<SyncCartQueue>(_onSyncCart, transformer: sequential());
  }
}

```

## 7. Provider Scoping & Lifecycle Rules

### 7.1 Scope Levels

* **Global Scope**: Use at app root (`MaterialApp.builder`) only for application-wide dependencies: `AuthBloc`, `ThemeCubit`.

* **Route / Feature Scope**: Provide at route entry point (`GoRoute` builder or Screen root). Automatically calls `close()` on the BLoC when popped.

* **Subtree Scope**: Passed via `BlocProvider.value` when passing an existing instance to a bottom sheet, dialog, or secondary route.

### 7.2 The `create` vs `.value` Rule

```
// CORRECT: Creating a NEW instance (Owner of lifecycle)
BlocProvider<OrderBloc>(
  create: (context) => OrderBloc(context.read<OrderRepository>())..add(const LoadOrder()),
  child: const OrderScreen(),
);

// CORRECT: Passing an EXISTING instance to a modal/dialog
Navigator.of(context).push(
  MaterialPageRoute(
    builder: (_) => BlocProvider.value(
      value: context.read<OrderBloc>(),
      child: const OrderModal(),
    ),
  ),
);

// FATAL ANTI-PATTERN: Creating inside .value (Never disposed, creates memory leak)
// BlocProvider.value(value: OrderBloc()) -> PROHIBITED

```

## 8. BuildContext Rules & Extensions

* **`context.read<T>()`**:

  * Use **only** inside event callbacks, gestures, or functions outside `build()` (e.g., `onPressed: () => context.read<CartBloc>().add(...)`).

  * **Prohibited** inside the `build()` method to render state.

* **`context.watch<T>()`**:

  * Subscribes the entire widget to all state changes. Use sparingly; prefer `BlocBuilder` or `context.select`.

* **`context.select<T, R>()`**:

  * Subscribes only to a specific sub-field `R`. Rebuilds only when `R` changes.

* **Async Guard**:

  * Always verify `if (!context.mounted) return;` after an `await` before touching `BuildContext`.

## 9. BLoC Widget Taxonomy

```
                     Does the widget trigger side effects
                     (Navigation, Dialogs, Snackbars)?
                                     │
                     ┌───────────────┴───────────────┐
                   [YES]                           [NO]
                     │                               │
         Does it ALSO rebuild the UI     Does it depend on a specific
           on that same state change?          sub-property only?
                     │                               │
             ┌───────┴───────┐               ┌───────┴───────┐
           [YES]           [NO]            [YES]           [NO]
             ▼               ▼               ▼               ▼
        BlocConsumer    BlocListener    BlocSelector    BlocBuilder

```

### Direct Usage Rules

1. **`BlocBuilder`**: Pure UI rendering. **Zero side effects allowed**. Never navigate, trigger popups, or dispatch mutations from inside the `builder` function.

2. **`BlocListener`**: Pure side-effects (routing, alerts, SnackBars). Does not rebuild widgets.

3. **`BlocConsumer`**: Combined Builder + Listener. Use when a state change requires both UI updates and a side effect (e.g., showing a failure toast and rendering the error screen).

4. **`BlocSelector`**: Limits rebuilds to a single property (e.g., watching `cart.items.length` without redrawing on price updates).

5. **Flattening Widget Trees**: Always combine multiple instances with `MultiBlocProvider` and `MultiBlocListener`.

## 10. Inter-BLoC Communication

**Rule: Never pass a BLoC directly into another BLoC.**

### Method 1: Shared Reactive Streams in Repositories (Preferred)

Both BLoCs subscribe to a stream exposed by a shared repository:

```
class CartBloc extends Bloc<CartEvent, CartState> {
  final AuthRepository _authRepository;
  StreamSubscription<User?>? _authSubscription;

  CartBloc(this._authRepository) : super(const CartInitial()) {
    on<CartReset>(_onReset);

    // Listens to stream on repository, NOT another BLoC
    _authSubscription = _authRepository.userStream.listen((user) {
      if (user == null) add(const CartReset());
    });
  }

  @override
  Future<void> close() {
    _authSubscription?.cancel();
    return super.close();
  }
}

```

### Method 2: Presentation-Layer Coordination

When an event in one BLoC needs to notify another at the view level:

```
BlocListener<AuthBloc, AuthState>(
  listenWhen: (previous, current) => current is AuthUnauthenticated,
  listener: (context, state) {
    context.read<CartBloc>().add(const ClearCart());
  },
  child: const AppNavigationShell(),
)

```

## 11. Strict Anti-Patterns & Prohibitions

1. **Missing Async Guards**: Never call `emit()` after an `await` without checking `if (isClosed) return;`.

2. **In-Place Collection Mutations**: Never mutate existing lists: `state.items.add(item); emit(state);`. Always construct a new list: `emit(state.copyWith(items: List.unmodifiable([...state.items, item])));`.

3. **Flutter Imports in BLoC**: BLoCs must never import `package:flutter/material.dart` or any UI-layer classes.

4. **Passing `BuildContext`**: Never pass `BuildContext` into BLoCs, Cubits, or Repositories.

5. **Instantiating BLoCs in Subtrees**: Never create a BLoC inside a widget's `build()` method with cascades (`BlocProvider(create: (_) => MyBloc()..add(Fetch()))`). Create at route boundary.

## 12. Direct AI Editor Rules (`.cursorrules` / System Instructions)

Copy this section directly into your `.cursorrules`, Cursor system prompt, or editor configuration:

```
# ENTERPRISE FLUTTER BLOC DIRECTIVES

1. ARCHITECTURE & SIMPLICITY:
   - Apply direct Repository architecture: BLoCs call Repositories directly.
   - Do NOT generate Use Cases, Interactors, or separate DataSource layers.
   - BLoCs, Cubits, Repositories, and Models must NEVER import `package:flutter/material.dart` or reference `BuildContext`.

2. MODELS & IMMUTABILITY:
   - All models MUST extend `Equatable` and implement `props`.
   - All models MUST use `@JsonSerializable(explicitToJson: true)` with `part '<file>.g.dart';`.
   - Implement factory `fromJson`, `toJson()`, and `copyWith()`.
   - NEVER mutate collections in-place. Always return `List.unmodifiable([...])`.

3. BLOC VS CUBIT:
   - Use `Bloc` with explicit Events and States for any asynchronous operations, search inputs, pagination, or multi-step logic.
   - Use `Cubit` ONLY for simple, synchronous local UI toggles (counters, flags, tabs).

4. DART 3 STATE MODELING:
   - Use Dart 3 `sealed class` hierarchies extending `Equatable` for mutually exclusive screen views.
   - In UI builders, render states exhaustively using modern Dart 3 `switch (state)` expressions.

5. CONCURRENCY:
   - Live search/input events MUST use a custom Rx debounce with `restartable()`.
   - Submit/action events MUST use `droppable()` from `package:bloc_concurrency`.
   - Always guard async emitters: verify `if (isClosed) return;` immediately after any `await` before calling `emit()`.

6. CONTEXT & LIFECYCLE:
   - Use `context.read<T>()` ONLY inside callbacks/event handlers. NEVER call `context.read<T>()` in `build()`.
   - Inside `build()`, use `BlocSelector` or `context.select<T, R>()` to prevent broad rebuilds.
   - Always check `if (!context.mounted) return;` when crossing async gaps before using `BuildContext`.
   - Use `BlocProvider(create: ...)` for new BLoCs; use `BlocProvider.value(value: ...)` ONLY for existing BLoCs.

7. WIDGET DISCIPLINE:
   - `BlocBuilder`: Pure UI rendering. ZERO side effects (no navigation, toasts, or dialogs).
   - `BlocListener`: Pure side effects. NEVER returns layout widgets.
   - `BlocConsumer`: Use only when combined rendering and side-effects are mandatory for the same state.
   - Coordinate cross-bloc operations via reactive streams in Repositories or UI-level `BlocListener`.

```

### 13.4 Presentation Layer: BLoC Implementation

```
// product_catalog_bloc.dart
import 'dart:async';
import 'package:flutter_bloc/flutter_bloc.dart';
import 'package:bloc_concurrency/bloc_concurrency.dart';
import 'package:rxdart/rxdart.dart';
import '../../repositories/product_repository.dart';
import 'product_catalog_event.dart';
import 'product_catalog_state.dart';

EventTransformer<E> debounce<E>(Duration duration) {
  return (events, mapper) => events.debounceTime(duration).switchMap(mapper);
}

class ProductCatalogBloc extends Bloc<ProductCatalogEvent, ProductCatalogState> {
  final ProductRepository _repository;
  static const int _pageSize = 20;

  ProductCatalogBloc(this._repository) : super(const ProductCatalogInitial()) {
    on<SearchQueryChanged>(
      _onSearchQueryChanged,
      transformer: debounce(const Duration(milliseconds: 300)),
    );

    on<NextPageRequested>(
      _onNextPageRequested,
      transformer: droppable(),
    );
  }

  Future<void> _onSearchQueryChanged(
    SearchQueryChanged event,
    Emitter<ProductCatalogState> emit,
  ) async {
    final cleanQuery = event.query.trim();
    if (cleanQuery.isEmpty) {
      emit(const ProductCatalogInitial());
      return;
    }

    emit(const ProductCatalogLoading());

    try {
      final items = await _repository.searchProducts(cleanQuery, page: 1, limit: _pageSize);
      
      // Thread-safety check across async boundary
      if (isClosed) return;

      emit(ProductCatalogLoaded(
        products: items,
        hasReachedMax: items.length < _pageSize,
        query: cleanQuery,
      ));
    } catch (e) {
      if (isClosed) return;
      emit(ProductCatalogError(e.toString()));
    }
  }

  Future<void> _onNextPageRequested(
    NextPageRequested event,
    Emitter<ProductCatalogState> emit,
  ) async {
    final currentState = state;
    if (currentState is! ProductCatalogLoaded || currentState.hasReachedMax) return;

    try {
      final nextPage = (currentState.products.length ~/ _pageSize) + 1;
      final newItems = await _repository.searchProducts(
        currentState.query,
        page: nextPage,
        limit: _pageSize,
      );

      if (isClosed) return;

      emit(
        newItems.isEmpty
            ? currentState.copyWith(hasReachedMax: true)
            : currentState.copyWith(
                products: List.unmodifiable([...currentState.products, ...newItems]),
                hasReachedMax: newItems.length < _pageSize,
              ),
      );
    } catch (e) {
      if (isClosed) return;
      emit(ProductCatalogError(e.toString()));
    }
  }
}

```

### 13.5 Presentation Layer: View Implementation

```
// product_catalog_screen.dart
import 'package:flutter/material.dart';
import 'package:flutter_bloc/flutter_bloc.dart';
import '../bloc/product_catalog_bloc.dart';
import '../bloc/product_catalog_event.dart';
import '../bloc/product_catalog_state.dart';

class ProductCatalogScreen extends StatelessWidget {
  const ProductCatalogScreen({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Catalog Search'),
        actions: [
          // Select only product count; avoids full screen redraws on pagination
          BlocSelector<ProductCatalogBloc, ProductCatalogState, int>(
            selector: (state) => state is ProductCatalogLoaded ? state.products.length : 0,
            builder: (context, totalCount) {
              return Center(
                child: Padding(
                  padding: const EdgeInsets.only(right: 16),
                  child: Text('Loaded: $totalCount'),
                ),
              );
            },
          ),
        ],
      ),
      body: Column(
        children: [
          Padding(
            padding: const EdgeInsets.all(12),
            child: TextField(
              decoration: const InputDecoration(
                hintText: 'Search products...',
                prefixIcon: Icon(Icons.search),
              ),
              onChanged: (query) {
                context.read<ProductCatalogBloc>().add(SearchQueryChanged(query));
              },
            ),
          ),
          Expanded(
            child: BlocConsumer<ProductCatalogBloc, ProductCatalogState>(
              listenWhen: (prev, curr) => curr is ProductCatalogError,
              listener: (context, state) {
                if (state is ProductCatalogError) {
                  ScaffoldMessenger.of(context).showSnackBar(
                    SnackBar(content: Text(state.message), backgroundColor: Colors.red),
                  );
                }
              },
              builder: (context, state) {
                return switch (state) {
                  ProductCatalogInitial() => const Center(
                      child: Text('Enter a query to find products.'),
                    ),
                  ProductCatalogLoading() => const Center(
                      child: CircularProgressIndicator(),
                    ),
                  ProductCatalogError(:final message) => Center(
                      child: Text('Error: $message'),
                    ),
                  ProductCatalogLoaded(:final products, :final hasReachedMax) =>
                    NotificationListener<ScrollNotification>(
                      onNotification: (scrollInfo) {
                        if (scrollInfo.metrics.pixels >= scrollInfo.metrics.maxScrollExtent - 200) {
                          context.read<ProductCatalogBloc>().add(const NextPageRequested());
                        }
                        return false;
                      },
                      child: ListView.builder(
                        itemCount: hasReachedMax ? products.length : products.length + 1,
                        itemBuilder: (context, index) {
                          if (index >= products.length) {
                            return const Center(
                              child: Padding(
                                padding: EdgeInsets.all(8),
                                child: CircularProgressIndicator(),
                              ),
                            );
                          }
                          final product = products[index];
                          return ListTile(
                            title: Text(product.name),
                            trailing: Text('\$${product.price.toStringAsFixed(2)}'),
                          );
                        },
                      ),
                    ),
                };
              },
            ),
          ),
        ],
      ),
    );
  }
}
```
