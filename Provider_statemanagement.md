# Enterprise Flutter Provider Architecture & AI Editor Directives

This document defines the production architecture, coding standards, and machine-readable instruction set for enterprise Flutter applications using **Provider** and **ChangeNotifier**. It enforces a direct Repository pattern, immutable models using `json_serializable` and `Equatable`, fine-grained widget rebuild strategies, explicit dependency injection, and lifecycle safety.

## 1. Architectural Principles

The application enforces a streamlined, feature-driven structure:

* **Direct Repository Pattern**: No separate Use Cases, Interactors, or DataSource layers. State notifiers (`ChangeNotifier`) communicate directly with Repositories.
* **Separation of Concerns**:
  * **Notifiers (`ChangeNotifier`)**: Hold state, execute business logic, manage debounce/async workflows, and interface with Repositories.
  * **Repositories**: Handle network calls (Dio/HTTP), local caching, and database queries. Repositories return domain models or throw domain-specific exceptions.
  * **Models**: Immutable data classes powered by `json_serializable` and `Equatable`.
  * **Views**: Pure declarative UI widgets subscribing to state via `Selector`, `Consumer`, or `context.select`. Zero business or networking logic inside views.

```
┌────────────────────────────────────────────────────────┐
│                   Presentation Layer                   │
│   ┌─────────────────────┐       ┌──────────────────┐   │
│   │ Flutter UI Widgets  │ ◄───► │  ChangeNotifier  │   │
│   │ (Consumer/Selector) │       │ (State & Logic)  │   │
│   └─────────────────────┘       └─────────┬────────┘   │
└───────────────────────────────────────────┼────────────┘
                                            │ calls directly
                                            ▼
┌────────────────────────────────────────────────────────┐
│                    Repository Layer                    │
│   ┌────────────────────────────────────────────────┐   │
│   │  Repository (Handles HTTP / DB / Local Cache)  │   │
│   └───────────────────────┬────────────────────────┘   │
└───────────────────────────┼────────────────────────────┘
                            │ parses into
                            ▼
┌────────────────────────────────────────────────────────┐
│                      Model Layer                       │
│   ┌────────────────────────────────────────────────┐   │
│   │   Models (Equatable + json_serializable)       │   │
│   └────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────┘
```

## 3. Model Specifications: `json_serializable` + `Equatable`

All models representing data transfer, entity structures, or UI payloads must strictly adhere to:

1. **Extend `Equatable`**: Enforce value equality via `props` (prevents redundant rebuilds when evaluating equality inside `Selector`).
2. **`@JsonSerializable()`**: Automated JSON serialization and deserialization (`part '<file>.g.dart';`).
3. **Deep Immutability**: All fields must be `final`. Modifications must be made via `copyWith()`. Never mutate internal collections in place.

### Standard Model Blueprint

```dart
import 'package:equatable/equatable.dart';
import 'package:json_annotation/json_annotation.dart';

part 'product_model.g.dart';

@JsonSerializable(explicitToJson: true)
class ProductModel extends Equatable {
  final String id;
  final String name;
  final double price;
  final bool isAvailable;
  final List<String> tags;

  const ProductModel({
    required this.id,
    required this.name,
    required this.price,
    this.isAvailable = true,
    this.tags = const [],
  });

  factory ProductModel.fromJson(Map<String, dynamic> json) =>
      _$ProductModelFromJson(json);

  Map<String, dynamic> toJson() => _$ProductModelToJson(this);

  ProductModel copyWith({
    String? id,
    String? name,
    double? price,
    bool? isAvailable,
    List<String>? tags,
  }) {
    return ProductModel(
      id: id ?? this.id,
      name: name ?? this.name,
      price: price ?? this.price,
      isAvailable: isAvailable ?? this.isAvailable,
      tags: tags ?? this.tags,
    );
  }

  @override
  List<Object?> get props => [id, name, price, isAvailable, tags];
}
```

## 4. Core Provider Types & Selection Matrix

| Provider Type | Mutability / Lifecycle | Primary Use Case |
| :--- | :--- | :--- |
| **`Provider<T>`** | Immutable value injection | Injecting Repositories, API Clients, or read-only service instances. |
| **`ChangeNotifierProvider<T>`** | Mutable; calls `dispose()` automatically | Providing feature-level ViewModels/Notifiers extending `ChangeNotifier`. |
| **`ProxyProvider<T, R>`** | Combines values; recalculates on `T` change | Injecting a service/repository `T` into an immutable class `R`. |
| **`ChangeNotifierProxyProvider<T, R>`** | Updates mutable `R` when dependency `T` updates | Connecting dynamic dependencies (e.g., injecting `AuthRepository` token into `CartProvider`). |
| **`MultiProvider`** | Tree flattening wrapper | Grouping multiple providers at app root or route boundary to prevent pyramid nesting. |

## 5. BuildContext Rules & Extension Methods

Strictly enforce where and how `BuildContext` extensions are consumed:

```
┌────────────────────────────────────────────────────────┐
│                   BuildContext Rules                   │
├───────────────────────┬────────────────────────────────┤
│ context.read<T>()     │ Inside callbacks & actions ONLY│
├───────────────────────┼────────────────────────────────┤
│ context.watch<T>()    │ Inside build() - Rebuilds ALL  │
├───────────────────────┼────────────────────────────────┤
│ context.select<T, R>()│ Inside build() - Rebuilds R    │
└───────────────────────┴────────────────────────────────┘
```

### 5.1 `context.read<T>()`
* Reads the instance **without subscribing** to changes.
* **Permitted**: Button callbacks (`onPressed`), gestures, lifecycle listeners, and functions invoked outside `build()`.
* **PROHIBITED**: Calling `context.read<T>()` directly in the `build()` method to render dynamic state values (it will not update when state changes).

```dart
// CORRECT: Invoking an action in a callback
ElevatedButton(
  onPressed: () => context.read<ProductCatalogProvider>().refresh(),
  child: const Text('Refresh'),
);
```

### 5.2 `context.watch<T>()`
* Reads the instance **and subscribes** the entire widget to all `notifyListeners()` events.
* **Use with caution**: Triggers a full widget rebuild whenever *any* property changes in the notifier.
* **PROHIBITED**: Inside event handlers (`onPressed`), `initState()`, or `dispose()`.

### 5.3 `context.select<T, R>(R Function(T) selector)`
* Subscribes the widget **only** to the specific computed value or property `R`.
* Rebuilds the widget **only when the selected slice changes value** (evaluated via `==`).
* Ideal for granular rebuild optimization without declaring nested widget builders.

```dart
// CORRECT: Rebuilds ONLY when the total count changes
@override
Widget build(BuildContext context) {
  final totalItems = context.select<CartProvider, int>((p) => p.items.length);
  return Text('Cart: $totalItems');
}
```

### 5.4 Async Gap Guard
Accessing `BuildContext` after an `await` without checking `context.mounted` causes runtime crashes if the widget unmounted during the async operation:

```dart
Future<void> _handleCheckout(BuildContext context) async {
  final confirmed = await showDialog<bool>(context: context, builder: ...);
  if (confirmed != true) return;

  // ASYNC GUARD: Prevents calling context on unmounted widget
  if (!context.mounted) return;

  context.read<CartProvider>().submitOrder();
}
```

## 6. UI Rebuilding Taxonomy: `Selector` vs. `Consumer`

```
                      Does the widget need to rebuild when
                          ANY property in state changes?
                                     │
                     ┌───────────────┴───────────────┐
                   [YES]                           [NO]
                     │                               │
             ┌───────┴───────┐               ┌───────┴───────┐
             │   Consumer    │               │   Selector    │
             │ (With static  │               │ (Subscribes   │
             │  child opt.)  │               │ to sub-field) │
             └───────────────┘               └───────────────┘
```

### 6.1 `Selector<ProviderType, SelectedValue>` (Recommended)
`Selector` extracts a specific property from the provider and rebuilds its builder **only** when that value changes according to `DeepCollectionEquality` or `Equatable`:

```dart
Selector<ProductCatalogProvider, bool>(
  selector: (_, provider) => provider.isLoading,
  builder: (context, isLoading, child) {
    if (isLoading) return const CircularProgressIndicator();
    return child!; // static child is not rebuilt
  },
  child: const Icon(Icons.check),
)
```

### 6.2 `Consumer<ProviderType>`
`Consumer` rebuilds whenever `notifyListeners()` is called. Always pass the static `child` parameter for subtrees that do not depend on the dynamic state:

```dart
Consumer<CartProvider>(
  builder: (context, cart, child) {
    return Column(
      children: [
        Text('Total: \$${cart.totalPrice}'),
        child!, // Static child is NOT rebuilt on notifyListeners()
      ],
    );
  },
  child: const CartDisclaimerHeader(),
)
```

## 7. Concurrency, Debouncing & Async State in ChangeNotifier

Unlike BLoC, Provider does not include built-in event concurrency transformers (`droppable`, `restartable`). You must explicitly manage debounce timers and execution locks inside the `ChangeNotifier`.

### 7.1 Safe Disposal and Async Guards
A `ChangeNotifier` that completes an asynchronous operation after being unmounted will throw:
`FlutterError: A ChangeNotifier was used after being disposed.`

**Mandatory Pattern**: Track `_disposed` and verify before every `notifyListeners()` call:

```dart
class BaseChangeNotifier extends ChangeNotifier {
  bool _disposed = false;

  bool get isDisposed => _disposed;

  @override
  void notifyListeners() {
    if (!_disposed) {
      super.notifyListeners();
    }
  }

  @override
  void dispose() {
    _disposed = true;
    super.dispose();
  }
}
```

### 7.2 Debouncing (Search Inputs)
Manage a private `Timer` inside the notifier to cancel and restart incoming input calls:

```dart
Timer? _debounceTimer;

void onSearchQueryChanged(String query) {
  _debounceTimer?.cancel();
  _debounceTimer = Timer(const Duration(milliseconds: 300), () {
    _performSearch(query);
  });
}

@override
void dispose() {
  _debounceTimer?.cancel();
  super.dispose();
}
```

### 7.3 Concurrency Lock / Droppable (Form Submissions)
Prevent duplicate API calls on rapid taps using a boolean guard flag:

```dart
bool _isSubmitting = false;

Future<void> submitPayment() async {
  // DROPPABLE GUARD: Ignore subsequent calls until first completes
  if (_isSubmitting) return;

  _isSubmitting = true;
  notifyListeners();

  try {
    await _repository.processPayment();
  } finally {
    _isSubmitting = false;
    notifyListeners();
  }
}
```

## 8. Scoping & Lifecycle Rules

### 8.1 The `create` vs. `.value` Contract

Violating this distinction is the leading cause of memory leaks and disposed-notifier crashes:

```dart
// CASE 1: Creating a NEW instance (Owner of lifecycle)
// Always use `create`. ChangeNotifierProvider will call dispose() on unmount.
ChangeNotifierProvider<OrderProvider>(
  create: (context) => OrderProvider(
    repository: context.read<OrderRepository>(),
  )..fetchOrders(),
  child: const OrderScreen(),
);

// CASE 2: Passing an EXISTING instance to a new Route or Dialog
// Always use `.value`. ChangeNotifierProvider will NEVER dispose the instance.
Navigator.of(context).push(
  MaterialPageRoute(
    builder: (_) => ChangeNotifierProvider.value(
      value: context.read<OrderProvider>(),
      child: const OrderDetailModal(),
    ),
  ),
);
```

> **FATAL ANTI-PATTERN**: Never call `ChangeNotifierProvider.value(value: OrderProvider())`. Because `.value` assumes an upstream widget manages the lifecycle, `dispose()` is never called, causing permanent memory leaks.

### 8.2 Scope Levels
1. **Global Scope (`main.dart`)**: Singletons that must survive the app lifecycle: `Provider(create: (_) => NetworkClient())`, `ChangeNotifierProvider(create: (_) => AuthProvider())`.
2. **Route Scope (Screen Boundary)**: Feature notifiers created in the screen route builder (`GoRoute` or `MaterialPageRoute`). Disposed automatically when popped.
3. **Modal/Sheet Scope**: Pass existing instances via `.value`.

## 9. Inter-Provider Communication

**Rule: Never pass a `ChangeNotifier` instance directly into another `ChangeNotifier` constructor.**

### Method 1: Injecting Repositories via Dependency Injection
Providers should synchronize through shared repositories or backend states rather than coupling to each other:

```dart
// Feature provider only depends on the Repository
class CartProvider extends BaseChangeNotifier {
  final CartRepository _repository;
  CartProvider({required CartRepository repository}) : _repository = repository;
}
```

### Method 2: Presentation-Layer Coordination
When an action in one provider requires an immediate action in another, coordinate them in the UI callback or listener:

```dart
ElevatedButton(
  onPressed: () {
    context.read<AuthProvider>().logout();
    context.read<CartProvider>().clearCart();
  },
  child: const Text('Logout'),
);
```

## 10. Strict Anti-Patterns & Prohibitions

1. **Calling `notifyListeners()` during build**:
   * ❌ Calling methods that invoke `notifyListeners()` inside the widget `build()` body.
   * *Error*: `"setState() or markNeedsBuild() called during build"`.
   * ✅ Move mutations to callbacks or `WidgetsBinding.instance.addPostFrameCallback`.

2. **Unchecked Collections Mutated in Place**:
   * ❌ `_items.add(newItem); notifyListeners();` (Reference equality prevents `Selector` from firing).
   * ✅ `_items = List.unmodifiable([..._items, newItem]); notifyListeners();`.

3. **Passing `BuildContext` to Notifiers**:
   * ❌ `void fetchUser(BuildContext context) async { ... }`
   * ✅ Notifiers must never know about Flutter UI constructs or `BuildContext`.

4. **Instantiating Notifiers inside `build()`**:
   * ❌ Instantiating a `ChangeNotifierProvider` with inline creation inside a child widget that frequently redraws.
   * ✅ Provide at route boundary.

5. **Omitting `isDisposed` Async Guard**:
   * ❌ Calling `notifyListeners()` after an `await` without verifying if the provider was disposed.
   * ✅ Always check `if (isDisposed) return;` prior to calling `notifyListeners()`.

Copy this block directly into your `.cursorrules`, Cursor system instructions, or IDE prompt file:

```

1. ARCHITECTURAL BOUNDARIES:
   - Apply direct Repository architecture: ChangeNotifiers call Repositories directly.
   - Do NOT generate Use Cases, Interactors, or separate DataSource layers.
   - ChangeNotifiers, Repositories, and Models must NEVER import `package:flutter/material.dart` or reference `BuildContext`.

2. MODEL STANDARDS:
   - All models MUST extend `Equatable` and implement `props`.
   - All models MUST use `@JsonSerializable(explicitToJson: true)` with `part '<file>.g.dart';`.
   - Implement `fromJson`, `toJson()`, and `copyWith()`.

   - Use `context.read<T>()` ONLY inside callbacks/event handlers. NEVER call `context.read<T>()` in `build()`.
   - Inside `build()`, use `context.select<T, R>()` or `Selector<T, R>` for granular rebuilds.
   - Use `Consumer<T>` only when the majority of the subtree depends on the provider; always pass the static `child` parameter.

   - All ChangeNotifiers MUST inherit from a base class or guard `notifyListeners()` with an `_disposed` check.

   - Throttle/drop submit actions using a boolean lock flag (`if (_isSubmitting) return;`).
   - Use `ChangeNotifierProvider(create: ...)` for new instances; use `ChangeNotifierProvider.value(value: ...)` ONLY for existing instances.
   - NEVER create a new notifier inside `ChangeNotifierProvider.value(...)`.

5. INTER-PROVIDER COMMUNICATION:
   - Do NOT inject one ChangeNotifier into another ChangeNotifier constructor.
   - Coordinate cross-provider operations via shared Repositories or UI-level callbacks.
```

```dart
class ProductRepository {
```

### 12.3 Provider Layer (`product_catalog_provider.dart`)

```dart
import 'dart:async';
import 'package:flutter/foundation.dart';
import '../models/product_model.dart';
import '../repositories/product_repository.dart';

enum CatalogStatus { initial, loading, success, error }

class ProductCatalogProvider extends ChangeNotifier {
  final ProductRepository _repository;
  static const int _pageSize = 20;

  ProductCatalogProvider({required ProductRepository repository})
      : _repository = repository;

  // Internal State
  CatalogStatus _status = CatalogStatus.initial;
  List<ProductModel> _products = const [];
  bool _hasReachedMax = false;
  String _errorMessage = '';
  String _currentQuery = '';
  int _currentPage = 1;
  bool _disposed = false;
  Timer? _debounceTimer;

  // Public Getters
  CatalogStatus get status => _status;
  List<ProductModel> get products => _products;
  bool get hasReachedMax => _hasReachedMax;
  String get errorMessage => _errorMessage;
  int get totalCount => _products.length;

  @override
  void notifyListeners() {
    if (!_disposed) {
      super.notifyListeners();
    }
  }

  /// Debounced search query handler
  void onSearchQueryChanged(String query) {
    _debounceTimer?.cancel();
    _debounceTimer = Timer(const Duration(milliseconds: 300), () {
      _executeSearch(query);
    });
  }

  Future<void> _executeSearch(String query) async {
    final cleanQuery = query.trim();
    if (cleanQuery.isEmpty) {
      _products = const [];
      _status = CatalogStatus.initial;
      _hasReachedMax = false;
      _currentQuery = '';
      notifyListeners();
      return;
    }

    _currentPage = 1;
    _hasReachedMax = false;
    _currentQuery = cleanQuery;
    _status = CatalogStatus.loading;
    notifyListeners();

    try {
      final results = await _repository.searchProducts(
        cleanQuery,
        page: _currentPage,
        limit: _pageSize,
      );

      if (_disposed) return;

      _products = List.unmodifiable(results);
      _hasReachedMax = results.length < _pageSize;
      _status = CatalogStatus.success;
      notifyListeners();
    } catch (e) {
      if (_disposed) return;
      _errorMessage = e.toString();
      _status = CatalogStatus.error;
      notifyListeners();
    }
  }

  /// Pagination loader
  Future<void> fetchNextPage() async {
    if (_hasReachedMax || _status == CatalogStatus.loading) return;

    try {
      final nextPage = _currentPage + 1;
      final newResults = await _repository.searchProducts(
        _currentQuery,
        page: nextPage,
        limit: _pageSize,
      );

      if (_disposed) return;

      if (newResults.isEmpty) {
        _hasReachedMax = true;
      } else {
        _currentPage = nextPage;
        _products = List.unmodifiable([..._products, ...newResults]);
        _hasReachedMax = newResults.length < _pageSize;
      }
      notifyListeners();
    } catch (e) {
      if (_disposed) return;
      _errorMessage = e.toString();
      notifyListeners();
    }
  }

  @override
  void dispose() {
    _disposed = true;
    _debounceTimer?.cancel();
    super.dispose();
  }
}
```

### 12.4 Presentation Screen (`product_catalog_screen.dart`)

```dart
import 'package:flutter/material.dart';
import 'package:provider/provider.dart';
import '../models/product_model.dart';
import '../providers/product_catalog_provider.dart';
import '../repositories/product_repository.dart';

class ProductCatalogScreen extends StatelessWidget {
  const ProductCatalogScreen({super.key});

  @override
  Widget build(BuildContext context) {
    // 1. Scoped route-level instantiation with dependency injection
    return ChangeNotifierProvider<ProductCatalogProvider>(
      create: (context) => ProductCatalogProvider(
        repository: context.read<ProductRepository>(),
      ),
      child: const _ProductCatalogView(),
    );
  }
}

class _ProductCatalogView extends StatelessWidget {
  const _ProductCatalogView();

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Catalog Search'),
        actions: [
          // 2. Granular rebuild: rebuilds ONLY when total count changes
          Selector<ProductCatalogProvider, int>(
            selector: (_, provider) => provider.totalCount,
            builder: (context, totalCount, _) {
              return Center(
                child: Padding(
                  padding: const EdgeInsets.only(right: 16),
                  child: Text('Loaded: $totalCount'),
                ),
              );
            },
          ),
        ],
      ),
      body: Column(
        children: [
          Padding(
            padding: const EdgeInsets.all(12),
            child: TextField(
              decoration: const InputDecoration(
                hintText: 'Search products...',
                prefixIcon: Icon(Icons.search),
              ),
              onChanged: (query) {
                // 3. context.read within user input callback
                context.read<ProductCatalogProvider>().onSearchQueryChanged(query);
              },
            ),
          ),
          Expanded(
            // 4. Selector targeting screen status and products
            child: Selector<ProductCatalogProvider, (CatalogStatus, bool, String)>(
              selector: (_, p) => (p.status, p.products.isEmpty, p.errorMessage),
              builder: (context, data, _) {
                final (status, isEmpty, errorMessage) = data;

                return switch (status) {
                  CatalogStatus.initial => const Center(
                      child: Text('Enter a query to find products.'),
                    ),
                  CatalogStatus.loading when isEmpty =>
                    const Center(child: CircularProgressIndicator()),
                  CatalogStatus.error when isEmpty =>
                    Center(child: Text('Error: $errorMessage')),
                  _ => const _ProductListView(),
                };
              },
            ),
          ),
        ],
      ),
    );
  }
}

class _ProductListView extends StatelessWidget {
  const _ProductListView();

  @override
  Widget build(BuildContext context) {
    // Rebuilds list view when products or reachedMax updates
    final products = context.select<ProductCatalogProvider, List<ProductModel>>(
      (p) => p.products,
    );
    final hasReachedMax = context.select<ProductCatalogProvider, bool>(
      (p) => p.hasReachedMax,
    );

    return NotificationListener<ScrollNotification>(
      onNotification: (scrollInfo) {
        if (scrollInfo.metrics.pixels >= scrollInfo.metrics.maxScrollExtent - 200) {
          context.read<ProductCatalogProvider>().fetchNextPage();
        }
        return false;
      },
      child: ListView.builder(
        itemCount: hasReachedMax ? products.length : products.length + 1,
        itemBuilder: (context, index) {
          if (index >= products.length) {
            return const Center(
              child: Padding(
                padding: EdgeInsets.all(8),
                child: CircularProgressIndicator(),
              ),
            );
          }
          final product = products[index];
          return ListTile(
            title: Text(product.name),
            trailing: Text('\$${product.price.toStringAsFixed(2)}'),
          );
        },
      ),
    );
  }
}
```
