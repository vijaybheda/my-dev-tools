# Enterprise Flutter GetX Architecture & AI Editor Directives

This document defines the production architecture, coding standards, and machine-readable instruction set for enterprise Flutter applications using **GetX**. It enforces a direct Repository pattern, immutable models using `json_serializable` and `Equatable`, reactive and simple state standards, explicit dependency injection via Bindings, and controller lifecycle safety.

## 1. Architectural Principles

The application enforces a streamlined, feature-driven structure:

* **Direct Repository Pattern**: No separate Use Cases, Interactors, or DataSource layers. GetX Controllers communicate directly with Repositories.
* **Separation of Concerns**:
  * **Controllers (`GetxController`)**: Exclusively hold observable state, handle user input, execute business logic, and interface with Repositories.
  * **Repositories**: Handle network calls (Dio/HTTP), local caching, and database queries. Repositories return domain models or throw domain-specific exceptions.
  * **Models**: Immutable data classes powered by `json_serializable` and `Equatable`.
  * **Views (`GetView`)**: Pure declarative UI widgets bound to a controller. Zero business or networking logic inside views.

```
┌────────────────────────────────────────────────────────┐
│                   Presentation Layer                   │
│   ┌─────────────────────┐       ┌──────────────────┐   │
│   │ GetView / UI Widget │ ◄───► │  GetxController  │   │
│   └─────────────────────┘  Obx  └─────────┬────────┘   │
└───────────────────────────────────────────┼────────────┘
                                            │ calls directly
                                            ▼
┌────────────────────────────────────────────────────────┐
│                    Repository Layer                    │
│   ┌────────────────────────────────────────────────┐   │
│   │  Repository (Handles HTTP / DB / Local Cache)  │   │
│   └───────────────────────┬────────────────────────┘   │
└───────────────────────────┼────────────────────────────┘

┌────────────────────────────────────────────────────────┐

└────────────────────────────────────────────────────────┘
```

## 3. Model Specifications: `json_serializable` + `Equatable`

All models representing data transfer, entity structures, or UI payloads must strictly adhere to:

1. **Extend `Equatable`**: Enforce value equality via `props` (prevents redundant reactive emissions when instances have identical values).
2. **`@JsonSerializable()`**: Automated JSON serialization and deserialization (`part '<file>.g.dart';`).
3. **Deep Immutability**: All fields must be `final`. Modifications must be made via `copyWith()`.

### Standard Model Blueprint

```dart
import 'package:equatable/equatable.dart';
import 'package:json_annotation/json_annotation.dart';

part 'product_model.g.dart';

@JsonSerializable(explicitToJson: true)
class ProductModel extends Equatable {
  final String id;
  final String name;
  final double price;
  final bool isAvailable;
  final List<String> tags;

  const ProductModel({
    required this.id,
    required this.name,
    required this.price,
    this.isAvailable = true,
    this.tags = const [],
  });

  factory ProductModel.fromJson(Map<String, dynamic> json) =>
      _$ProductModelFromJson(json);

  Map<String, dynamic> toJson() => _$ProductModelToJson(this);

  ProductModel copyWith({
    String? id,
    String? name,
    double? price,
    bool? isAvailable,
    List<String>? tags,
  }) {
    return ProductModel(
      id: id ?? this.id,
      name: name ?? this.name,
      price: price ?? this.price,
      isAvailable: isAvailable ?? this.isAvailable,
      tags: tags ?? this.tags,
    );
  }

  @override
  List<Object?> get props => [id, name, price, isAvailable, tags];
}
```

## 4. Reactive State (`Rx` / `Obx`) vs. Simple State (`GetBuilder`)

GetX offers two distinct state management mechanics. Enforce the following criteria:

| Feature / Criteria | Reactive (`Rx` / `Obx`) | Simple State (`GetBuilder`) |
| :--- | :--- | :--- |
| **Declaration** | `final count = 0.obs;` | `int count = 0;` |
| **Notification** | Automatic on value change (`count.value++`) | Manual via `update();` |
| **UI Consumer** | `Obx(() => Text('${controller.count.value}'))` | `GetBuilder<C>(builder: (c) => Text('${c.count}'))` |
| **Workers** | Compatible (`debounce`, `ever`, `interval`) | **Incompatible** (cannot attach workers) |
| **Memory Footprint** | Slightly higher (streams & listener overhead) | Ultra-lightweight (direct callback listeners) |
| **Use Cases** | Search queries, form inputs, dynamic updates | Massive static lists, bulk rendering, single redraws |

### Architectural Standard
* **Default to Reactive (`Rx` / `Obx`)** for all application state requiring stream-like transformations, user-input debouncing, or granular screen updates.
* **Use `GetBuilder`** exclusively when rendering very large lists where individual micro-stream subscriptions would introduce unwanted memory overhead.

## 5. Reactive Workers & Concurrency Handling

Workers execute side-effects whenever reactive variables (`Rx`) emit changes. Always initialize workers inside the controller's `onInit()` lifecycle method.

### Worker Types and Selection

```dart
class SearchController extends GetxController {
  final query = ''.obs;
  final tapCount = 0.obs;
  final cartItems = <ProductModel>[].obs;

  @override
  void onInit() {
    super.onInit();

    // 1. debounce: Ignores rapid calls until user stops typing for 300ms.
    // MANDATORY for: Search inputs, auto-complete queries.
    debounce(
      query,
      (value) => _performSearch(value),
      time: const Duration(milliseconds: 300),
    );

    // 2. interval: Throttles triggers, ignoring calls within the window.
    // MANDATORY for: Payment submit buttons, repeated tap protection.
    interval(
      tapCount,
      (_) => _submitOrder(),
      time: const Duration(seconds: 1),
    );

    // 3. ever: Triggers EVERY time the observable variable changes.
    // MANDATORY for: Auto-saving drafts, real-time analytics tracking.
    ever(cartItems, (items) => _recalculateTaxes(items));

    // 4. once: Fires only ONCE on the very first change, then auto-disposes.
    // MANDATORY for: Initial onboarding triggers, welcome tooltips.
    once(query, (_) => _logFirstSearchInteraction());
  }

  void _performSearch(String query) { /* ... */ }
  void _submitOrder() { /* ... */ }
  void _recalculateTaxes(List<ProductModel> items) { /* ... */ }
  void _logFirstSearchInteraction() { /* ... */ }
}
```

> **Note**: GetX automatically tracks and disposes workers bound inside `onInit()` when the controller is closed.

## 6. Dependency Injection & Bindings Architecture

Never instantiate or inject controllers directly inside widget `build()` methods. All dependencies must be registered through **Bindings** coupled to routes.

### 6.1 Binding Types & Lifecycle

* **`Get.lazyPut<T>()` (MANDATORY for routes)**: Instantiates the controller only when it is actually called by `Get.find<T>()`. Automatically deletes the instance from memory when the associated route is popped from the navigation stack.
* **`Get.put<T>()`**: Instantiates immediately. Avoid unless an instance must perform eager background tasks upon route registration.
* **`GetxService`**: Used for permanent, singleton services (e.g., `AuthService`, `StorageService`, `NetworkClient`) that must **never** be removed from memory.

### 6.2 Binding Implementation

```dart
import 'package:get/get.dart';
import '../controllers/product_catalog_controller.dart';
import '../repositories/product_repository.dart';

class ProductCatalogBinding extends Bindings {
  @override
  void dependencies() {
    // 1. Inject the Repository
    Get.lazyPut<ProductRepository>(() => ProductRepository());

    // 2. Inject the Controller, resolving the repository via Get.find()
    Get.lazyPut<ProductCatalogController>(
      () => ProductCatalogController(repository: Get.find<ProductRepository>()),
    );
  }
}
```

### 6.3 Route Registration via `GetPage`

Bind controllers to views declaratively in the routing configuration:

```dart
import 'package:get/get.dart';
import '../../features/product_catalog/bindings/product_catalog_binding.dart';
import '../../features/product_catalog/views/product_catalog_screen.dart';

abstract class AppRoutes {
  static const catalog = '/catalog';
}

abstract class AppPages {
  static final pages = [
    GetPage(
      name: AppRoutes.catalog,
      page: () => const ProductCatalogScreen(),
      binding: ProductCatalogBinding(),
      transition: Transition.fadeIn,
    ),
  ];
}
```

## 7. Controller Lifecycle Management

Extend `GetxController` and observe lifecycle methods properly:

```dart
class OrderController extends GetxController {
  // 1. onInit(): Variable initialization, workers, arguments parsing.
  // Context/UI is NOT yet rendered. Do NOT show dialogs or snackbars here.
  @override
  void onInit() {
    super.onInit();
    final args = Get.arguments; // Safely read route arguments
    _setupWorkers();
  }

  // 2. onReady(): Executed 1 frame AFTER the widget is rendered on screen.
  // SAFE for: Initial API calls, showing popups, checking permissions.
  @override
  void onReady() {
    super.onReady();
    _fetchInitialData();
  }

  // 3. onClose(): Teardown phase.
  // SAFE for: Disposing TextEditingControllers, custom stream subscriptions.
  @override
  void onClose() {
    // Custom cleanups (Workers registered in onInit are disposed automatically)
    super.onClose();
  }

  void _setupWorkers() {}
  void _fetchInitialData() {}
}
```

## 8. View Standards & `GetView`

### 8.1 The `GetView<T>` Contract
Always use `GetView<T>` for screens bound to a controller. It provides a direct, typed `controller` getter without calling `Get.find<T>()` repeatedly inside `build()`.

```dart
class ProductCatalogScreen extends GetView<ProductCatalogController> {
  const ProductCatalogScreen({super.key});

  @override
  Widget build(BuildContext context) {
    // Access controller directly via `controller` getter
    return Scaffold(
      appBar: AppBar(title: const Text('Catalog')),
      body: Obx(() {
        if (controller.isLoading.value) {
          return const Center(child: CircularProgressIndicator());
        }
        return ListView.builder(
          itemCount: controller.products.length,
          itemBuilder: (_, index) => ProductCard(product: controller.products[index]),
        );
      }),
    );
  }
}
```

### 8.2 The Critical `Obx` Golden Rule

> **FATAL RUNTIME ERROR**: `[Get] the improper use of a GetX has been detected. You should only use GetX or Obx for the flag you want to rebuild.`

An `Obx(() => ...)` widget **MUST** read at least one `.obs` variable synchronously inside its builder. If no `.obs` variable is accessed within the builder body, GetX throws a fatal runtime exception.

* ❌ **WRONG**: Wrapping static UI in `Obx`
  ```dart
  Obx(() => Text('Static Label')); // CRASH: No Rx variable read!
  ```
* ✅ **CORRECT**: Scoping `Obx` strictly around the dynamic widget
  ```dart
  Obx(() => Text(controller.userName.value));
  ```

## 9. Global Services & Inter-Controller Communication

### 9.1 Permanent Singletons via `GetxService`
For app-wide utilities (authentication session, secure storage, network interceptors), extend `GetxService`. A `GetxService` is never removed from memory:

```dart
class AuthService extends GetxService {
  final currentUser = Rxn<UserModel>();

  bool get isAuthenticated => currentUser.value != null;

  Future<AuthService> init() async {
    // Load session from disk
    return this;
  }

  void logout() {
    currentUser.value = null;
    Get.offAllNamed(AppRoutes.login);
  }
}

// In main.dart before runApp():
await Get.putAsync(() => AuthService().init());
```

### 9.2 Inter-Controller Communication
Do **not** tightly couple controllers to each other.
* **Option A (Shared Service)**: Inject the common `GetxService` into both controllers.
* **Option B (Reactive Listening)**: Listen to a reactive property on a globally available controller:
  ```dart
  class CartController extends GetxController {
    final AuthService _authService = Get.find<AuthService>();

    @override
    void onInit() {
      super.onInit();
      // Listen to auth changes without referencing an AuthController directly
      ever(_authService.currentUser, (user) {
        if (user == null) clearCart();
      });
    }

    void clearCart() {}
  }
  ```

## 10. Strict Anti-Patterns & Prohibitions

1. **`Get.put()` inside `build()`**:
   * ❌ Calling `final c = Get.put(MyController());` inside any widget's `build()` method.
   * ✅ Use route `Bindings` with `Get.lazyPut()`.
2. **Empty / Static `Obx` Blocks**:
   * ❌ Wrapping widgets that do not evaluate `.value` of an `Rx` variable inside `Obx`.
   * ✅ Keep `Obx` scoped directly to the leaf widget that reads the `.obs` variable.
3. **Passing `BuildContext` to Controllers**:
   * ❌ `controller.showDialog(context);`
   * ✅ Use GetX contextless APIs (`Get.dialog()`, `Get.snackbar()`) or trigger state that views listen to.
4. **Direct In-Place Mutation of Primitive Observables**:
   * ❌ Mutating properties of an object inside an `Rx` without updating the value or calling `.refresh()`.
   * ✅ Use `copyWith()` to assign a new instance: `user.value = user.value.copyWith(name: 'New');`.
5. **Collection Reassignment Anti-Pattern**:
   * ❌ `items.value = newItems;` (causes memory churn and breaks list observation).
   * ✅ Use reactive list helper methods: `items.assignAll(newItems);`.

## 11. AI Assistant Directives (`.cursorrules` / System Prompt)

Copy this block directly into your `.cursorrules`, Cursor system prompt, or editor configuration:

```
# ENTERPRISE FLUTTER GETX SYSTEM DIRECTIVES

1. ARCHITECTURAL BOUNDARIES:
   - Enforce direct Repository architecture: Controllers call Repositories directly.
   - Do NOT generate Use Cases, Interactors, or separate DataSource layers.
   - Controllers and Repositories MUST NEVER import `package:flutter/material.dart` or reference `BuildContext`.

2. MODEL STANDARDS:
   - All models MUST extend `Equatable` and implement `props`.
   - All models MUST use `@JsonSerializable(explicitToJson: true)` with `part '<file>.g.dart';`.
   - Implement `fromJson`, `toJson()`, and `copyWith()`.
   - Keep models deeply immutable.

3. STATE & CONTROLLER RULES:
   - Use Reactive state (`Rx`, `.obs`, `Obx`) by default.
   - Use `GetBuilder` ONLY for large, static lists where minimal memory overhead is strictly required.
   - Search inputs MUST be handled using the `debounce` worker inside `onInit()`.
   - Payment/submit buttons MUST be throttled using the `interval` worker inside `onInit()`.
   - Never call `Get.put()` inside a widget build method. All controllers must be bound via `Bindings` using `Get.lazyPut()`.

4. VIEW & WIDGET RULES:
   - Screen widgets MUST extend `GetView<TController>`.
   - Wrap ONLY reactive, `.obs`-reading leaf widgets with `Obx(() => ...)`.
   - NEVER wrap static widgets with `Obx`. It causes fatal runtime errors if no `.obs` is read.
   - Update reactive lists using `assignAll()`, `add()`, or `remove()`. Do NOT replace the list reference directly.

5. SERVICES & LIFECYCLE:
   - For permanent app-wide singletons, extend `GetxService` (never `GetxController`).
   - Network calls and async fetching must occur in `onReady()`, never in `onInit()`.
   - Dispose text editing controllers and custom subscriptions in `onClose()`.
```

```dart
import 'dart:async';
import '../models/product_model.dart';

class ProductRepository {
  // In production, inject network client (e.g. Dio)
  ProductRepository();

  Future<List<ProductModel>> searchProducts(
    String query, {
    required int page,
    required int limit,
  }) async {

        name: '$query Item ${(page - 1) * limit + index}',
        price: 19.99 + index,
```

### 12.3 Controller Layer (`product_catalog_controller.dart`)

```dart
import 'package:get/get.dart';
import '../models/product_model.dart';
import '../repositories/product_repository.dart';

enum CatalogStatus { initial, loading, success, error }

class ProductCatalogController extends GetxController {
  final ProductRepository _repository;
  static const int _pageSize = 20;

  ProductCatalogController({required ProductRepository repository})
      : _repository = repository;

  // Reactive state properties
  final searchQuery = ''.obs;
  final status = CatalogStatus.initial.obs;
  final products = <ProductModel>[].obs;
  final hasReachedMax = false.obs;
  final errorMessage = ''.obs;

  int _currentPage = 1;

  @override
  void onInit() {
    super.onInit();
    // Worker: debounces search input by 300ms
    debounce(
      searchQuery,
      (query) => _handleSearch(query),
      time: const Duration(milliseconds: 300),
    );
  }

  void onQueryChanged(String query) {
    searchQuery.value = query;
  }

  Future<void> _handleSearch(String query) async {
    final cleanQuery = query.trim();
    if (cleanQuery.isEmpty) {
      products.clear();
      status.value = CatalogStatus.initial;
      hasReachedMax.value = false;
      return;
    }

    _currentPage = 1;
    hasReachedMax.value = false;
    status.value = CatalogStatus.loading;

    try {
      final results = await _repository.searchProducts(
        cleanQuery,
        page: _currentPage,
        limit: _pageSize,
      );

      products.assignAll(results);
      hasReachedMax.value = results.length < _pageSize;
      status.value = CatalogStatus.success;
    } catch (e) {
      errorMessage.value = e.toString();
      status.value = CatalogStatus.error;
      Get.snackbar(
        'Error',
        errorMessage.value,
        snackPosition: SnackPosition.BOTTOM,
      );
    }
  }

  Future<void> fetchNextPage() async {
    if (hasReachedMax.value || status.value == CatalogStatus.loading) return;

    try {
      final nextPage = _currentPage + 1;
      final newResults = await _repository.searchProducts(
        searchQuery.value,
        page: nextPage,
        limit: _pageSize,
      );

      if (newResults.isEmpty) {
        hasReachedMax.value = true;
      } else {
        _currentPage = nextPage;
        products.addAll(newResults);
        hasReachedMax.value = newResults.length < _pageSize;
      }
    } catch (e) {
      Get.snackbar(
        'Pagination Error',
        e.toString(),
        snackPosition: SnackPosition.BOTTOM,
      );
    }
  }
}
```

### 12.5 Presentation View (`product_catalog_screen.dart`)

```dart
import 'package:flutter/material.dart';
import 'package:get/get.dart';
import '../controllers/product_catalog_controller.dart';

class ProductCatalogScreen extends GetView<ProductCatalogController> {
  const ProductCatalogScreen({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Catalog Search'),
        actions: [
          // Obx scoped strictly to the dynamic counter widget
          Obx(() => Center(
                child: Padding(
                  padding: const EdgeInsets.only(right: 16),
                  child: Text('Loaded: ${controller.products.length}'),
                ),
              )),
        ],
      ),
      body: Column(
        children: [
          Padding(
            padding: const EdgeInsets.all(12),
            child: TextField(
              decoration: const InputDecoration(
                hintText: 'Search products...',
                prefixIcon: Icon(Icons.search),
              ),
              onChanged: controller.onQueryChanged,
            ),
          ),
          Expanded(
            child: Obx(() {
              return switch (controller.status.value) {
                CatalogStatus.initial => const Center(
                    child: Text('Enter a query to find products.'),
                  ),
                CatalogStatus.loading && controller.products.isEmpty =>
                  const Center(child: CircularProgressIndicator()),
                CatalogStatus.error && controller.products.isEmpty => Center(
                    child: Text('Error: ${controller.errorMessage.value}'),
                  ),
                CatalogStatus.success || controller.products.isNotEmpty =>
                  NotificationListener<ScrollNotification>(
                    onNotification: (scrollInfo) {
                      if (scrollInfo.metrics.pixels >=
                          scrollInfo.metrics.maxScrollExtent - 200) {
                        controller.fetchNextPage();
                      }
                      return false;
                    },
                    child: ListView.builder(
                      itemCount: controller.hasReachedMax.value
                          ? controller.products.length
                          : controller.products.length + 1,
                      itemBuilder: (context, index) {
                        if (index >= controller.products.length) {
                          return const Center(
                            child: Padding(
                              padding: EdgeInsets.all(8),
                              child: CircularProgressIndicator(),
                            ),
                          );
                        }
                        final product = controller.products[index];
                        return ListTile(
                          title: Text(product.name),
                          trailing:
                              Text('\$${product.price.toStringAsFixed(2)}'),
                        );
                      },
                    ),
                  ),
              };
            }),
          ),
        ],
      ),
    );
  }
}
```
